# Game Hub working rules

- Follow PROMPT.md and STRUCTURE.txt. On resume, pull the verified private remote without rewriting history, then read HANDOFF.md, PROGRESS.md, DECISIONS.md and the design index. Run the full existing test suite and build first; fix any baseline failure with small, safe steps before starting new work. Follow the exact next step.
- Route work to the build roles in the design plan (simulate roles one at a time with labeled outputs if sub-agents cannot be spawned). Design comes before implementation. Update the relevant design file and DECISIONS.md before changing the design in code.
- Respect previous work: follow `docs/design/` and existing patterns; do not rewrite, refactor, rename, restructure, or delete existing code unless the current task requires it (and record why in DECISIONS.md). Note anomalies under Open questions in HANDOFF.md with the smallest safe fix.
- Use the four Review Council roles (Advocate, Critic, Neutral Analyst, Judge) on the overall plan and at each milestone gate. Record the Judge's verdict in docs/reviews and address required changes within two re-review rounds.
- Keep progress and handoff current after each task, including exact next step, in-progress work, fragile spots, open questions, and `Last worked on by: <model/tool>, <date>`. Write a Tutor entry per milestone. Tag every upcoming task `[simple]` or `[complex]`; smaller models defer `[complex]` tasks and note that in HANDOFF.md. Keep going across tasks and milestones with a brief 3–5 line status after each milestone, stopping only for owner tasks, irreversible decisions, completion, or tool limits. Preserve green main and push unfinished work on a `wip/<task>` branch when stopping early.
- Check tests and the staged diff before small commits. Confirm the intended GitHub repository is private before pushing, verify visibility after changes, and never force-push. Release only milestone tags through the Windows build.
- Keep v1 offline and user data out of Git. Use Windows Graphics Capture for the exact foreground game window. The app has no injection, game hooks, or memory reads. Keep all files, code, and technical docs in English and the UI accessible in English and Arabic. Never ask the owner to relay messages between agents or share passwords/tokens in chat.
