# Requirements

These requirements trace to the product specification, principally sections 3–11. The build prompt adds the private repository, release, and review gates. The [implementation plan](08-implementation-plan.md) orders delivery. The [manual checklist](../TESTING.md) records evidence for Windows-specific behaviors.

| ID | Requirement | Acceptance criteria |
| --- | --- | --- |
| R1 | Discover and display the game library | Parse Steam `libraryfolders.vdf` and `appmanifest_*.acf`, Epic `.item` manifests, and supported Xbox/Game Pass folders and packages. Manually add a selected `.exe`. Persist results in SQLite and display name, source, install path, last played, total playtime, and optional local cover art. Repeat scans without duplicate entries. A missing launcher or malformed individual manifest leaves other entries available. Document Xbox limitations and offer manual add when the executable is accessible. |
| R2 | Track sessions from the tray | Detect known games started through any launcher and record start, end, and duration. Show tracking status from a single tray instance. Opening and closing a known game produces one correct session with consistent library totals. Switch between games without attributing foreground work to the wrong session. Optional Windows startup follows the user's setting. |
| R3 | Preserve recent screenshots | Default to one capture every 30 seconds and a ring of ten captures. Both limits are configurable. Capture the known foreground game window via a permitted Windows API only. Skip minimized, unfocused, unavailable, or unusable black frames. Retain the latest valid captures in order when the session ends and display those files on the game page. |
| R4 | Save voice and text notes | When enabled, the close popup offers voice recording, text, and dismissal for its originating session. Default Ctrl+Alt+N starts or stops a short voice note while a tracked game is focused. The recorder enforces a maximum of 60 seconds and allows early stop. Saved notes remain attached to the originating game and session even if focus changes. Microphone denial or device failure leaves text entry usable. |
| R5 | Restore context and launch a game | Show the small always-on-top Last time card when a known game starts. Display the recent voice and text notes, last moments carousel, last played, total playtime, and controls card. Honor autoplay settings. Default Ctrl+Alt+L reopens context. The game page Play action presents the card before dispatching the launcher URI or executable. Clear empty states and launch errors preserve context. Exclusive fullscreen is documented and the Play flow offers a reliable way to view context first. |
| R6 | Pin controls and review session history | Default Ctrl+Alt+C pins an image of the focused tracked game window. The game page accepts a supported local image and per-game free text. Show all recorded sessions in chronological order with date, duration, screenshots, and notes. Preserve usable timeline entries if an individual media file is missing. |
| R7 | Expose settings in English and Arabic | Settings cover language, capture interval, ring size, voice autoplay, close popup, all three hotkeys, Windows startup, and the data folder. Persist valid changes across restart. Report invalid values and registration conflicts. All visible app text, including tray and error states, follows the selected language. Arabic applies RTL layout across the UI. |
| R8 | Keep user data local and durable | Use SQLite and app-managed media and logs under `%LOCALAPPDATA%\GameHub\` by default. Core functions work offline. The app makes zero network requests. Configured launcher dispatch hands off to the installed Windows handler. There are no accounts, analytics, or paid APIs. Keep user data, media, logs, and credentials out of Git. Verify that completed sessions and saved notes survive restart without crossing game boundaries. |
| R9 | Provide a responsive, accessible, non-invasive app | Aim for near-zero idle CPU, poll processes every 2–3 seconds, and stop capture when a known game has no eligible foreground window. Never inject into, hook, or read game memory. One malformed launcher input, failing device, or unavailable per-game capture leaves the rest of the app usable. Core screens work by keyboard and show clear focus, translated errors, legible contrast, and no clipped content at common Windows DPI scales. |
| R10 | Distribute a usable private Windows build | Target Windows 10/11 and develop in Python 3.12+ with PySide6. A milestone release from M0 onward carries a PyInstaller `GameHub.exe` distribution and Inno Setup `GameHub-Setup.exe`, with changelog notes and click-through installation. The private `game-hub` repository has green test CI. M8 verifies installation, window/tray, and launch from a clean Windows system without Python. English developer and installation instructions and the requested short Arabic user guidance accompany the release. |
| R11 | Keep the core available for future modules | Separate the game library, session events, repositories, and Windows adapters from the memory UI. The design identifies extension points for replay, Google Drive backup, transcription, note search, Launch Doctor, and Mods & Arabic Translations. The v1 deliverables contain only the shared core and Game Memory. |

## Scope exclusions

Video replay buffers, Google Drive backup, local transcription, note search, Launch Doctor, and the Mods & Arabic Translations installer are future work. The application excludes injected overlays, game process hooks or memory access, networking, accounts, telemetry, and paid APIs in v1.
