# GameRewind v1.2.0-rc.3 — Speed, Size & Security Re-Check Design

**Date:** 2026-11-24  
**Baseline:** [docs/perf/baseline-rc2.md](../perf/baseline-rc2.md)  
**Scope:** Zero new user features. Reduce local workspace bloat and shipped bundle size, accelerate startup/library/idle/exit performance, and re-verify security from scratch with fresh independent red-team agents.

---

## Part A — Size Reduction

1. **Workspace hygiene (`A1`):**
   - Remove historical local build folders (`dist\m1..m4`, `dist\GameHub`, `dist\debug`, `dist\clean`, `dist\verified`, `dist\Portable Smoke`, stale `.zip` files), `build\`, `.pytest_cache\`, and `.ruff_cache\`.
   - Keep `.venv\` (uninstalling unneeded `opencv-python` locally too).
   - Standard PyInstaller invocation (`PyInstaller --noconfirm --clean packaging/gamerewind.spec`) overwrites `dist\GameRewind` in place.

2. **Shipped bundle shrinking (`A2` — targets: Portable `.zip < 70 MB`, Installed `< 200 MB`):**
   - **Remove OpenCV (`cv2`, 125.55 MiB unpacked):**
     - `windows_capture/__init__.py` imports `cv2` at top level solely for `Frame.save_as_image()` and `DxgiDuplicationFrame.save_as_image()`, neither of which GameRewind calls (GameRewind reads `frame.frame_buffer` and encodes WebP via Pillow).
     - Register a minimal in-memory `cv2` shim (`_ensure_cv2_shim()` in `gamehub/core/capture/windows.py`) before importing `windows_capture`. Any attribute access on the shim raises a clear `RuntimeError`.
     - Remove `opencv-python` from `requirements.txt`, exclude `cv2` in `packaging/gamerewind.spec` (`excludes=['psutil', 'cv2', ...]`), uninstall transitive `opencv-python` in CI before running tests/PyInstaller, and update `packaging/THIRD_PARTY_NOTICES.txt`.
     - Verify WGC capture works in the frozen bundle without `cv2`.
   - **Trim unused PySide6 & Pillow artifacts:**
     - Retain `PySide6-Addons` strictly for `QtMultimedia` (Ogg Vorbis voice playback via FFmpeg plugin) and keep all Qt/FFmpeg/PortAudio/libsndfile/CPython license notices.
     - Exclude unused PySide6 modules (`QtQml`, `QtQuick`, `QtOpenGL`, `QtSvg`, `QtMultimediaWidgets`, `QtPdf`, `QtSql`, `QtWebEngine*`, etc.).
     - Filter `analysis.binaries` / `analysis.datas` in `packaging/gamerewind.spec` to drop:
       - `opengl32sw.dll` (19.68 MiB)
       - `Qt6Quick*.dll`, `Qt6Qml*.dll`, `Qt6OpenGL*.dll`, `Qt6VirtualKeyboard*.dll`, `Qt6Svg*.dll`, `Qt6MultimediaWidgets*.dll`, `Qt6Pdf*.dll`, `Qt6ShaderTools*.dll`
       - Unused plugins (`qdirect2d.dll`, `qminimal.dll`, `qtiff.dll`, `qgif.dll`, `qicns.dll`, `qtga.dll`, `qsvg.dll`, `qwbmp.dll`, `qtvirtualkeyboardplugin.dll`, `qtuiotouchplugin.dll`, `qsvgicon.dll`, `qnetworklistmanager.dll`, Qt `tls/*` backends)
       - Unused `PySide6/translations/*.qm` except English/Arabic (`qtbase_ar.qm`, `qtbase_en.qm`)
       - `PIL/_avif*.pyd` (7.53 MiB, unused AVIF codec)
     - Keep `upx=False` and `qoffscreen.dll` (required for CI headless smoke tests).
   - **CI Size Gate:**
     - Add an explicit size assertion in `.github/workflows/windows.yml` failing the release job if `GameRewind-Portable-*.zip > 70 MiB` (`73,400,320` bytes) or unpacked `dist/GameRewind > 200 MiB` (`209,715,200` bytes).

## Part B — Speed Optimization

1. **Startup (`B1`):**
   - Preserve exact security initialization order: `ProtectionGuard.self_check()` runs FIRST before `migrate_legacy_data_root()`, `SingleInstance.claim_or_activate()`, window creation, or DB writes; `protection_guard.start()` starts immediately before `window.show()`; startup TOCTOU `protection_guard.check_once()` still runs strictly before `mods_engine.recover_incomplete()`, `GlobalHotkeys`, and `watcher.start()`.
   - Lazy-initialize `VoicePlayer` (`PySide6.QtMultimedia` / `QMediaPlayer` / `QAudioOutput`) on first `play()` or `is_available()` call instead of during startup (saves FFmpeg/QtMultimedia DLL load time and idle RAM).
   - Lazy-import `PIL.Image` inside `gamehub/core/capture/service.py` `_encode()`.
   - Show `window.show()` immediately with cached theme/language applied, then populate the library grid and finish secondary subsystem wiring (`ModsEngine`, `SessionWatcher`, `CaptureService`, `GlobalHotkeys`, `LibraryController.refresh()`) on the first event-loop ticks without blocking window appearance.
   - Defer `_refresh_game_panels()` in `_wire_mods` until the user opens Translations & Mods or a Game Page, and cache `ModsEngine.is_game_protected()` results keyed by `(game_id, install_dir, protection_mode, dir_mtime)` so navigating to Mods is instantaneous instead of rescanning every install directory on every click.

2. **Library & Covers (`B2`):**
   - Use canonical `320×150` disk-cached WebP cover thumbnails so card resizing never misses the disk cache or re-decodes full images.
   - Move cover disk-cache reads, source image scaling (`QImageReader`), rounded cropping (`QPainter` on `QImage`), and WebP cache writes onto a bounded background `ThreadPoolExecutor` (`max_workers=2`), delivering `QImage` back to the UI thread via `QueuedConnection` to convert to `QPixmap` and store in the bounded LRU cache (`_MAX_CACHE_ITEMS = 192`).
   - Show lightweight placeholder pixmaps immediately and prioritize viewport-visible cards (lazy-loading off-screen cards as the user scrolls) so 100+ games render smoothly with minimal RAM growth and zero UI-thread full-image decoding or network I/O.
   - Defer `QMenu` construction inside `GameCard` until the overflow button is clicked.

3. **Safety-Critical Exit Latency (`B3` — targets: p95 < 200 ms, max < 300 ms normal & under UI load):**
   - Make `ProtectionGuard`'s emergency exit path completely independent of the Qt UI thread: when `hard_exit_on_emergency=True`, `_on_guard_trigger` and `_on_guard_failure` call `os._exit(code)` directly on the `protection-guard` daemon thread (zero `QueuedConnection` wait, zero 200 ms fallback timer, zero blocking log flush). Windows kernel immediately cleans up hotkeys, handles, pipes, and WGC sessions.
   - Keep `hard_exit_on_emergency=False` using the clean `guard_bridge` Qt shutdown path for unit tests.
   - Precompute a single `dict[str, ProtectionTrigger]` policy lookup map on `ProtectionGuard.__init__` / `update_policy()` for O(1) per-process matching.

4. **Near-Zero Idle CPU (`B4`):**
   - Use public Win32 `kernel32.K32EnumProcesses` (~0.06 ms CPU, zero process handles opened) on fast `80 ms` ticks to detect any change in the active PID set:
     - If PID set is unchanged: skip `CreateToolhelp32Snapshot` (~6.5 ms CPU saved per tick).
     - If any new PID appears (or `K32EnumProcesses` fails/overflows): immediately execute full `CreateToolhelp32Snapshot` + policy check (detecting protected game starts in ~45–95 ms).
     - Run read-only `WindowsServiceProbe.running_services()` every 3rd tick (~240 ms, ~0.00 ms CPU) and an unconditional full `CreateToolhelp32Snapshot` audit every 2.0 s as belt-and-suspenders against PID reuse.
   - `self_check()` and direct `check_once()` always run a full `Toolhelp32` + `SCM` scan unconditionally.
