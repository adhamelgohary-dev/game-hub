# Manual Windows test checklist

Run these checks as their milestone becomes available. Record milestone and commit, Windows version and build, app version, DPI, launcher or fixture class, and a pass, fail, or blocked result for each applicable row. Keep user files and identifying game or machine details out of shared evidence. Use a test profile for fault-injection and location-change tests.

| Check | Action | Pass condition |
| --- | --- | --- |
| M0 · Window and tray | Start the test build, open it twice, close the main window, reopen via tray, and quit via tray. | One app instance opens, the tray remains available after closing the window, and Quit exits. |
| M0 onward · Release files | Open the private milestone release, check its notes and download both the one-folder distribution and `GameHub-Setup.exe`. Run the starter release from both paths. | Release notes match the milestone changelog. Both downloads start the window and tray via standard Windows interactions. |
| M1 · Library | Refresh with installed Steam and Epic games and an available Xbox/Game Pass title. Try a missing launcher or malformed synthetic manifest and add a test `.exe` manually. | Supported titles persist across restart without duplicate rows. Bad inputs leave other games available. Xbox limitations and manual-add outcomes are reported. |
| M2 · Sessions | Start and close a known game, then repeat while another known game is open. Compare timeline rows and totals with a stopwatch, allowing for the polling interval at each boundary. | Every tracked game run closes once with correct attribution, duration, and totals. Tray status matches active sessions. |
| M2 · Idle performance | Close known games, minimize to tray, let the app settle, and sample app CPU for at least 60 seconds with Task Manager or Performance Monitor. Record rate, hardware, and Windows build. | Idle usage stays near zero without recurring work beyond process polling, and no capture work runs. Investigate sustained visible CPU use before approval. |
| M3 · Capture and ring | Set a short supported interval, produce at least eleven visibly distinct foreground frames with a ten-slot ring, then close the game. Repeat with Alt-Tab, minimize, protected or black capture, and another foreground application. | Exactly the ten latest valid frames display for the ended run. Ineligible intervals add no frames, and no image of another app or the desktop is retained. An unavailable frame does not end tracking. |
| M4 · Voice and text | Toggle the voice hotkey while a game is focused, record up to the maximum, close during recording, and try again after disabling microphone permission. Save text in the close prompt and dismiss a separate prompt. | Audio can play back, stops by 60 seconds, and stays on the originating session. Microphone failure leaves text entry usable. Dismissal creates no note. |
| M5 · Last time and Play | Seed history, launch through Steam, then launch through GameRewind Play. Toggle autoplay, reopen via the hotkey, and try exclusive fullscreen and a failing launch handoff. | Each startup shows the right completed history once. Play shows context before dispatch. Autoplay follows its setting. Fullscreen recovery and launch errors permit access to history. |
| M6 · Controls and timeline | Pin a controls image in-game, upload a local image, add text, and browse old and new sessions. Remove a media file in a test profile. | Controls remain associated with the correct game and the timeline exposes dates, durations, notes, and available shots. A missing file affects only its entry. |
| M7 · Settings and startup | Change capture defaults, notes, and bindings. Register a test binding in another app and attempt to replace a working binding with it. Toggle Windows startup and sign in again. Open the current data folder and exercise a test-profile location change. | Valid settings survive restart. A conflict identifies the affected binding and keeps the previous binding working. Startup follows the setting. A failed location change preserves existing data. |
| M7 · Arabic and accessibility | Traverse every surface with keyboard in English and Arabic. Try 100%, 150%, and 200% scale, long labels, mixed-script game titles, and the Windows screen reader. | Text is translated and Arabic layout mirrors. Paths and key chords remain legible. Keyboard traversal, focus indicator, accessible names, contrast, scrolling, and error feedback work at each scale. |
| M8 · Clean install | On clean Windows without Python, download the milestone release, run `GameHub-Setup.exe`, open GameRewind, inspect the tray, and also start the unpacked one-folder distribution. Check the installed app offline. | Both release paths start and can be used offline. Add a test executable and verify data survives restart. Download and install steps require only standard Windows interactions. |

Also confirm during relevant milestones that no Windows Graphics Capture fallback reads another application's pixels, local data never enters the repository, and the application makes no network requests. Inspect app and child-process attribution when launching through an installed launcher.
